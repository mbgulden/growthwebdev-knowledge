# OKF skill hub Phase A — snapshot all skill stores into the hub

## Context

- Skills existed in 17 unversioned locations: 12 Hermes profile dirs
  (215 SKILL.md files), `~/.antigravity/skills/` (24 files, not a git repo),
  and 4 prismatic-engine stores (44 files).
- Inventory found **12 divergent skill names** (same name, different content
  across profiles) and 59 shared-identical names — silent drift confirmed.
- A broken self-referential symlink in the orchestrator profile was
  injecting ~16 phantom copies of one skill into agent prompts every turn
  (fixed 2026-08-20; ~500 tokens/turn recovered).
- The engine already has a skill-distribution substrate (GRO-4362/4363:
  `prismatic skills sync` bootstrapper, 4-tier resolution, dashboard Skills
  tab) but no shared upstream source.

## Decision

1. **Phase A (this PR):** mirror all three stores 1:1 into `okf/skills/`
   (hermes/<profile>/, agy/, prismatic/<store>/), generated by
   `scripts/skill-hub-snapshot.py`, with `index.md` (human catalog +
   divergent backlog) and `index.json` (sha256 manifest).
2. **Per-profile folders are the unit of truth** — divergence is preserved,
   never auto-merged.
3. **Sync direction: profiles → hub** (hub is the registry/mirror).
   Flipping to hub-as-source later is a Phase B flag change.
4. **Distribution (Phase B)** extends the existing engine bootstrapper with
   `--source <okf-checkout>` + hermes/agy target backends. The engine reads a
   plain git checkout — it never depends on the OKF MCP, keeping the engine
   portable to any computer with `git clone + prismatic skills sync`.
5. **Drift reconciliation** is a deliberate per-skill act driven by the
   ⚠ section of `okf/skills/index.md`, not a bulk merge.

## Consequences

- First git-versioned history of every skill (Hermes + AGY + engine).
- The 12 divergent names become an explicit backlog in index.md.
- Re-running the generator after skill changes makes the index diff the
  change report.
- 22 MB added to the hub (2,444 files) — acceptable for a versioned registry.

## Open / next

- Phase B: engine `--source` flag + hermes/agy backends (engine lane; file
  Linear ticket once this lands).
- Phase C: dashboard "sync from hub" + per-skill drift reconciliation.
- Daily regeneration cron (no-agent, silent-when-clean) — propose after
  Phase A merge.
