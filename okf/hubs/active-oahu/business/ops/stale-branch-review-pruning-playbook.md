## Safe pruning criteria

A stale branch can be deleted only if all are true:

1. No open PR uses the branch as `headRefName`.
2. The branch tip is reachable from `origin/main` **or** its changes are patch-equivalent to `origin/main` **or** a linked Linear issue/OKF report confirms it was superseded.
3. It is not one of the allowed long-lived branches: `main`, `staging`, `master`, `deploy-fresh`.
4. The owner/dependency review finds no active worktree, cron, or deployment process depending on it.
5. The deletion is recorded in OKF or a PR comment with branch name, evidence, and command output.

## Review commands

For each candidate branch:

```bash
BR=origin/example-branch

gh pr list --repo mbgulden/active-oahu-tours-mirror \
  --state open \
  --head "${BR#origin/}" \
  --json number,title,url

git merge-base --is-ancestor "$BR" origin/main && echo reachable || echo not-reachable

git cherry -v origin/main "$BR" | sed -n '1,40p'

git diff --stat origin/main..."$BR" | sed -n '1,80p'
```

If all checks prove the branch is safe to delete:

```bash
git push origin --delete "${BR#origin/}"
git fetch origin --prune
```

## Why deletion is not automatic

Branch deletion is irreversible in normal GitHub workflows and can destroy context for old PRs, stale agent worktrees, or audit reports. The governance guard therefore reports candidates but never deletes them.

## Definition of done for stale branch cleanup

- Each branch has one of: deleted, retained with reason, or converted into a new active PR/task.
- Guard `stale-branches` becomes pass, or retained branches are encoded into `allowed_long_lived_branches` with rationale.
- OKF records include the final branch decision table.
- Watchdog remains enabled after cleanup to catch new stale branches.
