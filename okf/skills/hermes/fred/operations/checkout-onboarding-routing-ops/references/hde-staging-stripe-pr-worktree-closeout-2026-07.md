# HDE staging Stripe + PR/worktree closeout pattern (2026-07)

## When to use

Use this note when Human Design Engine staging needs to absorb Stripe/onboarding work plus loose PR/worktree output before launch.

## What happened

A staging launch request required three parallel tracks:

1. Bring Stripe/payment/onboarding code from the active HDE working tree into `hd-platform-staging`.
2. Verify the HDE staging bundle without leaking secrets or claiming full-suite green.
3. Close loose Ned/OpenHumanDesignMCP PR/worktree state.

## Durable lessons

### 1. Treat `staging` as the runtime target, but respect branch-prefix governance

The HDE staging repo may have a real local `staging` branch, but repo hooks can still reject direct push because the branch name does not match allowed agent prefixes.

Pattern:

- Commit the verified work locally on/for `staging` when that is the runtime target.
- If direct push to `staging` is blocked by branch-prefix governance, do **not** bypass hooks.
- Push the same verified commit on a governance-compliant `feature/...` branch.
- Record explicitly that local `staging` contains the commit and the feature branch is the pushable handoff.
- Add Linear evidence with the commit SHA, branch names, verification scope, and exact hook blocker.

### 2. Secret scan must include generated bytecode/caches before commit

A repo-wide secret scan surfaced a generated `__pycache__/*.pyc` with token-like Stripe bytes even though the source files were intended for staging/test use.

Pattern:

- Remove generated caches before staging/committing: `find . -type d -name __pycache__ -prune -exec rm -rf {} +`.
- Exclude runtime/generated dirs (`dist`, `node_modules`, `.git`, `docker/data`, `test-results`) from scans.
- Exclude `.env*` from git operations, but still inspect env availability safely/redacted when verifying Stripe runtime.
- Report only prefixes/length/mode/account check status for Stripe keys.

### 3. HDE Stripe staging verification contract

Before saying the Stripe/onboarding bundle is staged, run at least:

- `python3 -m py_compile` over changed Python API/payment/router/orchestrator/test files.
- Focused payment pytest, for example:
  - `payment/test_local_sig.py`
  - `payment/test_webhook_validation.py`
  - `payment/test_transit_bundle_webhooks.py`
  - `payment/test_printful.py`
  - `test_phase17_onboarding.py`
- `npm run build` for Astro/static changes.
- Secret scan over repo-safe files.
- Stripe `/v1/account` check using server key, reporting prefix/length/mode/account id only.

Label this **ad hoc targeted verification**, not full suite green, unless a canonical full suite actually ran.

### 4. Bring only safe staging artifacts

Safe/expected classes:

- payment server/static checkout code
- Stripe webhook route changes
- success/onboarding pages and calm one-step UX
- tenant router/orchestrator staging scripts
- focused payment tests and PWP QA harness
- launch docs/runbooks

Avoid committing:

- `.env*` and backup envs
- `docker/data`
- runtime reports
- generated `__pycache__`
- visual snapshot bulk unless intentionally required
- unrelated media or scratch outputs

### 5. Ned/OpenHumanDesignMCP loose-end pattern

When Ned has a local HD/MCP branch and open PRs:

- Merge clean, green dependency PRs first when checks pass.
- Rebase Ned’s branch on current `origin/main` and run local tests.
- If a `ned/...` push is lane-blocked because stale remote history contains out-of-lane `.github/workflows/*`, do not bypass.
- Create a clean `feature/...` Fred handoff branch carrying the tested diff.
- Open/merge a PR from that branch after checks pass.
- Remove unrelated local scratch files (for example `result.md`) rather than committing them.
- If local `main` diverges only because the same patch exists upstream under a different SHA, verify patch-id equivalence before resetting local main to `origin/main`.

## Evidence shape to record

```text
HDE:
- commit: <sha> [Fred] ... (#GRO-xxxx)
- branches containing commit: staging, feature/...
- py_compile: passed
- focused pytest: N passed
- npm run build: passed
- secret scan: passed
- Stripe account check: ok, sk_test/sk_live prefix only
- governance blocker if staging push rejected

OpenHumanDesignMCP:
- dependency PR merged
- handoff PR URL
- checks status
- local pytest result
- open PR count after merge
```
