# Telegram pinned master prompt continuity

## Lesson

A Telegram-pinned mega prompt is useful as a human-accessible bookmark, but it is not a dependable recurring operating context for George. Do not assume pinned-file contents are automatically injected into each future turn.

For Prismatic coordination, use the pinned mega prompt as a stable charter/constitution only. Current state must come from the durable handoff plus direct-source re-verification.

## Recommended continuity pattern

1. Treat the North Star / mega prompt as the stable doctrine: mission, authority boundaries, stop-the-line rules, verification discipline, and scale gates.
2. Treat `PRISMATIC_CURRENT_HANDOFF.md` as the live truth index, but still re-check direct sources before acting.
3. Maintain a small resume checkpoint for the exact active slice: worktree, branch, base/head/tree, changed paths, logs/hashes, current verdict, and next gate.
4. Before long canonical suites, independent review loops, or work likely to hit Hermes tool-iteration ceilings, write/update the handoff or checkpoint first so interruption does not strand uncommitted state.
5. After a tool-ceiling interruption, resume from the last durable checkpoint and direct-source readback, not from stale values embedded in the mega prompt.
6. If a pinned prompt contains dated PRs/SHAs/runtime values, classify those as historical reset evidence until reverified.

## Pitfall

Do not answer “yes, pinning keeps George on track” without qualification. Pinning helps Michael navigate the reference, but George stays on track by maintaining durable, current, short control artifacts and verifying live sources.
