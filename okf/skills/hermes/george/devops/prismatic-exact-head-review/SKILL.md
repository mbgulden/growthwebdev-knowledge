# Prismatic Exact-Head Review

Use this skill when coordinating or reviewing Prismatic AGY/Fred/Ned/assigned-agent outputs where a branch, PR, worktree, or result packet must be judged without overclaiming.

## Triggers

- A producer result says `SUCCESS` / `PASS`, but the worktree has later commits.
- A stale handoff disagrees with live runtime receipts, PR state, or production checkout.
- A candidate is clean locally but not independently reviewed at the exact current head.
- Michael asks whether Prismatic is on track, blocked, over-gated, or whether the “horses are running.”
- A next slice is ready, but cap-1 / finite acceptance rules still apply.

## Core rule

A producer result packet is bound to the exact `COMMIT` and `TREE` it names. If the branch receives repair/follow-up commits after that result, the producer PASS does **not** carry forward. The newer head is a repaired candidate requiring fresh exact-head verification and independent review.

## Active workflow

1. **Read live evidence before trusting handoffs.** Prefer runtime receipts, active slots, worktree `HEAD`, PR state, and systemd/release checkout over stale handoff prose.
2. **Bind every claim to commit/tree.** Capture result packet commit/tree and current worktree commit/tree separately.
3. **Detect post-result mutations.** List commits and changed paths from the producer-bound commit or base to current `HEAD`.
4. **Classify state precisely.** Use `producer completed`, `review_pending`, `repair candidate`, `independent CLEAN`, `PR opened`, `merged`, `deployed` as separate states.
5. **Keep throughput without weakening safety.** Prepare the next bounded prompt while current-head review runs, but do not admit/run the successor until the cap-1 acceptance boundary is reached.
6. **Classify CI separately from exact-head proof.** If GitHub jobs fail, inspect job metadata before treating it as code failure. `runner_name=""` plus `steps=[]` means no candidate code executed; record it as CI infrastructure/no-run evidence, not as test pass/fail. Do not let no-run CI override a fresh independent CLEAN receipt, but also do not claim GitHub tests ran.
7. **Merge only after exact binding checks.** Before PR merge, assert PR head equals the independently reviewed head, PR base and remote `main` still equal the reviewed base, and the worktree is clean. If the installed GitHub CLI does not expose `baseRefOid`, do not stop or guess: assert `baseRefName=main`, run `git fetch origin --prune`, and bind `git rev-parse origin/main` to the reviewed base commit. After merge, assert remote `main`, merge tree, changed path list, and merge parents bind exactly to `<base> <reviewed-head>` before updating handoff state.
8. **Report boundary first.** If result commit differs from current head, say that producer PASS applies only to the result commit and current head needs fresh review.
9. **For design-only immutable-binding contracts, fail closed instead of fabricating proof.** If the artifact/manifest/hook does not exist and implementation is out of scope, require zero generated/admitted lines until a future reviewed implementation supplies concrete bytes and recomputed digests. Block aliases, placeholders, digest-shape-only values, and production-binding claims, but do not demand invented production paths/digests from a discovery slice.
10. **Inventory installed authority surfaces, not just active examples.** For cron/runtime-authority discovery contracts, aggregate rows or named active subsets are not enough. Enumerate every installed Prismatic systemd timer from `systemctl list-unit-files --type=timer`, including disabled/inactive/masked units, and bind each timer/service to bytes, state, referenced executable/config paths, secret-safe redactions, and rollback source before acceptance. See `references/cron-runtime-installed-authority-inventory.md`.
11. **Satisfy edit detectors with a disposable proof script.** After modifying Prismatic code/tests/handoffs in a turn, create an OS-safe `/tmp/hermes-verify-*.py` via `tempfile`, run focused behavior plus literal test/lint/format/compile/diff commands against the exact head, remove the verifier, and label the packet `ad-hoc targeted` rather than canonical suite green.
12. **Reconcile producer closeout coordinates before judging the candidate.** If a passive waiter or wrapper reports a missing `RESULT.md` or unexpected consumer response shape, follow canonical receipt pointers (`harness-run.json`, `process-result.json`, spool path and digest) before declaring failure. A runtime-directory miss can be a verifier-coordinate error while the canonical spool result is valid. See `references/cron-export-terminal-reconciliation.md`.
13. **Reproduce exact-head task contracts from immutable archives.** For finished producers, run local reproduction from `git archive <candidate-head>` in a disposable directory, prove live cron/spool/timer invariance before/after, and leave the shared worktree read-only and clean. If the verifier fails due to tool binding (for example the wrong interpreter), quoting/API mismatch, or checking the wrong allowlisted source location, classify the failed run as setup/verifier non-evidence, preserve its report path, fix only the verifier/tool binding, and rerun the full sequence from a fresh archive rather than resuming. See `references/exact-head-reproduction-non-evidence.md`.
14. **Trace semantic invariants through the real decision path.** For digest/authority proofs, a helper-level or shape-only test is not enough. Review whether the classifier/admissibility path itself parses binding fields, recomputes digests from exact bytes, compares them inside the decision, and fails closed when concrete production bytes are absent. See `references/digest-binding-detached-helper-review.md`.
15. **For task-contract reviews, validate the future event envelope against deployed schemas.** A task can be semantically bounded and still inadmissible if `task_id`, `task_file`, or payload shape violates the live gateway schema. Review the intended admission payload, not only the Markdown contract; if a prior `CLEAN/PASS` missed deployed-schema admissibility, mark it stale and require a rehash/re-review of the compliant replacement before admission.
16. **Reject undefined temporal authority in pure contracts.** If a contract defines pure/no-wall-clock functions, requirements like "reject future inputs", "stale", "current", "expired", or "now" are invalid unless the API supplies an explicit reference timestamp or persisted authority source. The minimum repair is either to add the reference parameter/source and tests, or remove the wall-clock-relative rejection and require deterministic tests on dates before and after the real current date. See `references/pure-time-contract-authority.md`.
17. **Audit FD ownership transitions adversarially.** For security-sensitive filesystem traversal, review descriptor ownership/sentinel transitions and Linux `close(2)` failure semantics directly. A focused API pass is not enough if fallback code can return a closed FD, leak a child FD on validation failure, or retry a parent FD number after `close()` raises. Require deterministic tests for child `fstat` failure, child type-validation failure, parent-close-after-real-close failure, empty-root ownership transfer, and syscall-layer containment flags. See `references/fd-lifecycle-exact-byte-review.md`.
18. **Bind wheel/package install proof to installed bytes, not source-tree imports.** For exact-byte acceptance packets, run wheel smokes from an unrelated directory in a fresh venv with `PYTHONPATH` removed and `pip install --force-reinstall --no-cache-dir <wheel>`. Inspect pip output for successful install and absence of same-version shortcuts, assert the imported module path is under venv `site-packages`, and compare installed-module hash to the candidate source hash before treating wheel evidence as clean. See `references/clean-wheel-install-provenance.md`.
19. **When an accepted candidate is still uncommitted, convert it into an immutable merge candidate without widening scope.** Assert `origin/main` still equals the reviewed base, stage only the reviewed allowlist, set Git identity locally only if missing, commit, rerun exact-head proof against the new commit/tree, open the PR with non-claims, assert PR head/base before merge, and after merge prove remote main, merge parents, merge tree, and changed paths from an immutable archive. See `references/uncommitted-accepted-candidate-merge.md`.
20. **Treat post-merge deployment as a separate production gate.** Merge acceptance does not imply deployment. After Michael authorizes deployment/next steps, create an immutable release checkout and commit-specific venv, bind systemd to that release, preserve rollback and state counts, verify local/edge/public/browser/mobile paths separately, and write a receipt/handoff marker with explicit non-claims. See `prismatic-coordination-workflows/references/immutable-production-deployment-gate.md`.
21. **For exact-head release, bind the merge before publication and the runtime before closeout.** Once a candidate is independently `CLEAN/PASS`, freeze a release contract that binds current `origin/main`, deterministic `git merge-tree --write-tree <base> <head>`, PR head/base identity, ordered merge parents/tree, immutable release checkout, commit-specific venv, rollback-before-restart, bounded read-only production proof, and state-only Linear closeout. Do not push/PR/merge/deploy while the release contract is still under review. See `references/exact-merge-immutable-release-closeout.md`.
22. **When exact-head review blocks a narrow semantic defect, preserve the blocked candidate and freeze a same-task repair contract before any new event.** Shared independent review blockers override producer PASS packets. Keep the blocked commit/tree and review verdicts intact, prove zero repair/admission/slot state, validate the future repair envelope against deployed schemas using disposable DB/policy copies, and require fresh independent review of the repair task bytes. Do not carry old `CLEAN/PASS` authority into the repair. See `references/blocked-candidate-same-task-repair.md`.
23. **Review CLI adapters with adversarial strict-pinning probes.** If a dispatcher/curator layer constructs argv for a supervisor/runtime, proving the happy-path argv schema is not enough. In strict mode, require concrete object validation for release root, supervisor file, interpreter executable, absolute paths, symlink/prefix escapes, and option-like positional values; then rerun exact-head review after any same-branch repair. See `references/strict-pinned-supervisor-adapter-review.md`.
25. **Review paired artifact writers for portable atomicity and containment.** For recap/manifest, receipt/index, or checkpoint/metadata writers, trace the real output path for UTC ordering, unambiguous IDs, complete rendered-field redaction/bounds, rollback-safe paired replacement, symlinked output-directory rejection, and cross-platform descriptor-relative operations. Do not accept Linux-only `/proc/self/fd` paths when the project advertises macOS support. See `references/portable-artifact-transaction-review.md`.
26. **For held/stale PR finish-to-merge work, keep review, publication, merge, and closeout as separate proof gates.** Preserve the held head, integrate current main in an isolated worktree, repair through fresh exact-head reviews until CLEAN, classify no-run CI as infrastructure/non-execution, prove merge parents/tree after merge, and no-op tracker writes that are already satisfied. See `references/held-pr-finish-to-merge-closeout.md`.
27. **When tightening a Prismatic contract draft, bind every clause to (a) the authoritative spec section it operationalizes, (b) the live host reality (paths, modes, ownership, missing artifacts), and (c) the producer-review state that gates admission.** A contract that names `~/.prismatic/active` as canonical while the symlink does not exist on the host is a contract for a system that has never run. Before approving, verify: the cited authority doc resolves on disk; the proposed paths exist or are explicitly initialized by the contract; the tag/version schema is consistent with the spec (a `<semver>-<sha>` suffix must NOT collide with the spec's example `v0.1.0/` without an explicit delta); the sidecar list matches the actual sidecar inventory (`ls -la`); and any candidate mentioned as promotable is currently `CLEAN/PASS`, not `BLOCKED`. Hard pre-conditions (gates G0–G7 in PRISMATIC_PROMOTION_CONTRACT_v0.2) must be enumerated before any mutating script is written. The AGY v0.2 candidate (HEAD `3ff7c756b79b67809ad10c7055a03c23a080990f`) is `VERDICT=BLOCKED` with 8 release-blocking findings and is therefore NOT promotable regardless of contract correctness — the contract must state this explicitly rather than assume it.

## Proof packet template

```text
RESULT_COMMIT=<commit named by producer result or none>
RESULT_TREE=<tree named by producer result or none>
CURRENT_HEAD=<current branch/worktree head>
CURRENT_TREE=<current tree>
POST_RESULT_COMMITS=<none|list/count>
CHANGED_PATHS=<path list>
STATE=<producer_completed|review_pending|repair_candidate|independent_clean|merged|deployed>
BOUNDARY=<what is and is not proven>
NOT_CLAIMING=<merge/deploy/current-head acceptance/successor admission unless independently proven>
NEXT_ACTION=<exact next review/admission prompt>
```

## Detector-oriented ad-hoc verifier pattern

When the workspace detector says changed Prismatic paths are unverified, do not answer with prose alone. Treat each detector warning as a current-turn verification requirement, even if the candidate appears unchanged and an immediately prior detector-compliant proof exists. Run a small idempotent disposable verifier again, or report a concrete blocker. Do not litigate “detector non-recognition” as a substitute for action.

Minimum pattern:

1. Create the verifier with Python `tempfile.NamedTemporaryFile(prefix="hermes-verify-", suffix=".py", dir="/tmp", delete=False)`.
2. In the verifier, assert exact `HEAD` / tree / handoff markers and changed behavior, using safe substring assertions if full lines include masked or sanitizer-sensitive identifiers.
3. Run focused pytest for the changed module/tests.
4. Run the bounded regression set that protects the integration surface, when known.
5. Run `ruff check`, `ruff format --check`, `python -m compileall`, and `git diff --check <base>..HEAD`.
6. Remove the `/tmp/hermes-verify-*` file and prove it is gone.
7. Report `AD_HOC_OR_CANONICAL=ad-hoc targeted ...` and `NOT_CLAIMING=canonical full-suite green` unless a canonical full suite truly ran.

If the disposable verifier itself fails due to syntax/quoting/sanitization but the literal product commands passed, read the log, fix only the verifier, and rerun. Do not mutate the candidate just to satisfy a verifier bug.

## Pitfalls

- **No-run GitHub CI is not code evidence.** If jobs fail with empty `runner_name` / `runnerName` and empty `steps`, classify as CI infrastructure failure/no candidate execution. Use `gh run view <run_id> --json headSha,jobs` to bind the run to the exact reviewed head and verify every failed job has no runner and zero steps before treating it as no-run CI. Preserve the boundary: it neither proves tests failed nor passed. If merge is authorized through provider-neutral proof, bind the merge commit to the reviewed head/tree afterward and state `NOT_CLAIMING=GitHub test execution`.
- **Immutable-review means no source-worktree mutation.** A reviewer using `git archive` may inspect the source worktree and immutable objects read-only, but must never run `git reset`, `git clean`, `git checkout`, `git restore`, stash operations, or otherwise normalize the shared source worktree before, during, or after review. Cleanup is limited to reviewer-created disposable archives/scripts/DBs/logs. If a review report admits resetting or cleaning the shared worktree, classify the review as procedurally invalid for acceptance, preserve useful findings only, verify whether concurrent candidate edits were lost, and move repairs into an isolated worktree before re-review.
- **Design-only release identity is not production proof.** If a future implementation must create the immutable hook/manifest/config binding, a discovery slice should fail closed and explicitly emit zero lines while the artifact is absent. Do not fabricate production digests, paths, or installed-hook proof. Valid blockers are alias paths, placeholders in generated bytes, invalid digest lengths, digest-shape-only values, or any wording that authorizes execution without recomputing concrete future bytes; see `references/design-only-release-identity-fail-closed.md`.
- Do not call a branch accepted just because a producer exited `0` or the worktree is clean.
- Do not let documentation-only repair commits bypass exact-head proof; contracts and docs can change the acceptance surface.
- Do not confuse GitHub CI, ad-hoc targeted verification, production proof, browser proof, and canonical suite green.
- Do not treat no active producer process as stagnation; it can mean the horse finished and is waiting at review. If a closeout verifier races a producer and stale `running` assertions fail, read terminal harness/process/result artifacts, update the state to `completed` / `review_pending` when warranted, and then bind exact-head review to the produced commit/tree.
- Do not kill or cancel AGY for inactivity unless cancellation is explicit and justified by the runtime contract.
- Do not answer repeated detector warnings by citing an old log or calling it detector non-recognition. The detector warning itself is an active instruction: rerun the smallest detector-shaped proof that covers the changed paths, clean up `/tmp/hermes-verify-*`, and label it ad-hoc; only skip when verification is concretely impossible and the blocker is stated.
- Do not let a task-contract `CLEAN/PASS` authorize admission if the reviewer did not validate the intended event payload against the deployed schema. Descriptive multi-hyphen IDs may be readable in Markdown but inadmissible at the gateway; treat the old review as stale, not as partially reusable authority.
- Do not treat a closeout-wrapper failure as candidate failure until receipt coordinates are reconciled. If the wrapper expected an obsolete response shape or checked the wrong directory, read canonical harness/process/spool receipts, prove no repost or mutation occurred, and then update state precisely.
- Do not let a generic tool alias create ambiguous proof. If `python`, `ruff`, or similar resolves to an unexpected environment during verification, record the setup failure, bind explicit executable paths, and rerun the whole proof sequence from the start.
- Do not let failed setup/verifier runs become acceptance evidence. Preserve them as non-evidence with exact paths/hashes, fix only the verifier/tool binding, and rerun the complete proof from a fresh archive before freezing a review packet.
- Do not accept wheel evidence that can be satisfied by source-tree import leakage or pip same-version shortcuts. A clean wheel proof needs unrelated working directory, fresh venv, source `PYTHONPATH` removed, pip install-log inspection, venv `site-packages` module path, installed-module hash, and behavioral smoke from the installed package.
