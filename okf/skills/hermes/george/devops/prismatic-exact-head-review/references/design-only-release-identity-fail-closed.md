# Design-only release identity: fail closed instead of fabricating production bytes

Session pattern: CRONRUNTIME-1 / GRO-4319 reviewed a documentation-only contract for cron runtime authority. A reviewer correctly blocked a candidate that used a semantic-version path (`/releases/v1.0.0`) and invalid digest-shaped example. The repair had to preserve the design-only boundary: no current `pe-cron-trigger` artifact existed in any release, and source implementation/production mutation were out of scope.

Reusable rule:

- When an upstream contract says a release manifest/hook binding does not yet exist, do **not** invent a production path, release digest, config digest, or installed-hook proof just to satisfy an immutable-binding review.
- For a design/discovery slice, the correct durable contract can be fail-closed: record the absence, provide a concrete absence canary if useful, prohibit generated cron lines while the artifact is missing, and require future implementation slices to recompute real artifact/config/manifest digests before any install/admission.
- Semantic-version aliases (`v1.0.0`, `latest`), shortened commit directories, symlinked release paths, mutable worktrees, unresolved placeholders in generated bytes, and digest-shape-only values remain blockers.
- Non-production fixture digests are allowed only if labeled as schema/validator fixtures and explicitly rejected by active deployment policy. They must still be valid 64-lowercase-hex SHA-256 values.
- The review question is whether the contract can emit an unbound invocation or overclaim installed proof. If it cannot emit and clearly fails closed until concrete future artifact bytes exist, do not demand fabricated production bytes from a design-only slice.

Suggested exact-head review probes:

```text
VERSION_ALIAS_COUNT=0
FULL_COMMIT_PATH_GRAMMAR=true
ABSENT_HOOK_YIELDS_ZERO_LINES=true
FIXTURE_DIGEST_LENGTHS=64
PRODUCTION_BINDING_CLAIMED=false
LIVE_MUTATION=false
ONE_PATH_CONTAINMENT=true
```

Reporting boundary:

```text
AD_HOC_OR_CANONICAL=ad-hoc targeted contract/review verification
NOT_CLAIMING=production hook artifact, cron installation, live migration, PR, merge, or independent acceptance unless separately proven
```
