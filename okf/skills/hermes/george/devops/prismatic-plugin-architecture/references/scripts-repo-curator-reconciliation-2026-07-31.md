# Scripts-repo curator reconciliation — 2026-07-31

Use this as a compact reference when reviewing Prismatic helper/orchestrator script branches that appear to add curator, verifier, janitor, cron, or cleanup capabilities outside the PE core repo.

## Situation pattern

A helper branch can contain useful built-first work while still being unsafe to merge wholesale:

- dozens of heterogeneous commits across operational scripts, runtime-state ignores, WIP checkpoints, merge commits, bytecode artifacts, and vendored PE code;
- dirty shared checkout state, so evidence must come from immutable Git objects/archives;
- no configured remote/PR path, making a direct local merge unreviewable;
- helper-local `prismatic/curator` packages that shadow the canonical PE curator.

## Durable review sequence

1. Freeze exact `main`, feature head, feature tree, ahead count, changed-path manifest, dirty-state inventory, untracked inventory, and remote configuration.
2. If the checkout is dirty, review immutable archives/object data rather than normalizing the shared checkout.
3. Compare feature code to the PE master plan and canonical PE modules before accepting new copies as authoritative.
4. Reject wholesale merge when commits are heterogeneous. Preserve the branch and extract clean slices from `main`.
5. Establish repository/publication authority before any merge: no configured remote means no PR/review path.
6. Separate artifact preservation from deletion: `.bak`, orphan, worktree, cron, and database cleanups require manifests and explicit approval gates.

## Curator-specific finding pattern

PE already owns the canonical curator package (`prismatic/curator/SPEC.md`, `lane.py`, `dispatcher.py`, `issue_to_task.py`, review-lane tests, health surface). A scripts-repo copy labeled as vendored/supervisor support is not a canonical PE curator unless it preserves the canonical contracts.

Reject a vendored curator as canonical when it:

- removes review-only lane protections;
- changes default Linear priority semantics;
- embeds supervisor-specific branch or heartbeat instructions into shared translation logic;
- omits the canonical lane/dispatcher/spec/tests.

Correct integration:

1. Pin the live curator service to an immutable PE release/venv before relying on restart durability.
2. Replace scripts-repo vendoring with a thin fail-closed adapter that imports canonical `prismatic.curator.issue_to_task` from an explicit immutable PE package root.
3. Assert imported module provenance immediately after import.
4. Keep AGY `--dir` workspace selection separate from Python package authority; workspace/cwd must never choose curator bytes.
5. Put supervisor-specific branch/task heartbeat text in a versioned supervisor prompt adapter, not in the shared curator translator.
6. First slice is pure tests/provenance/no producer launch; real AGY canary comes later under cap-1 and runtime authority.

## Health/verifier architecture

Profile-specific checks belong in a removable Hermes-operations adapter/plugin that emits versioned read-only health artifacts/findings. PE Core owns plugin lifecycle, provenance, policy, artifacts, and dashboard visibility. The curator may classify/route findings. Cleanup execution belongs behind the governed action broker and explicit approval gates.

Fold one-shot verifiers into a persistent fixture-driven health framework. Include fixtures for stale paths, directory entries, moved/deleted files, false-positive prevention, cron JSON shape, state DB thresholds, worktree ownership, branch divergence, source-generated bytecode, broken symlinks, and curator/service provenance.

## Pitfalls from this session

- Do not equate `all current temp files removed` with proof of a claimed historical byte count unless the historical receipt is durable.
- Do not run a verifier that creates/deletes Git branches, writes `.pyc` into source, kills port owners, or depends on mutable local hooks.
- Ignore rules do not untrack already-tracked compiled artifacts; stop bytecode writes first, then remove tracked bytecode in a separately reviewed source slice.
- A pool of 52 directories may be valid multi-repo checkouts, not broken worktrees. Classify by owner/use/evidence before proposing deletion.
- A large SQLite DB with a large freelist/FTS index needs retention/index/reclaim planning, backup, quiescence, integrity, and rollback—not ad-hoc live `VACUUM`.
- A broken absolute symlink into a mutable PE checkout should be reconnected through a pinned release wrapper/adapter, not copied or relinked to mutable source.
