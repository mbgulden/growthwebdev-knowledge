# GRO-4347/4348/4349 Verification (2026-07-28)

## GRO-4347 — FareHarbor Calendar Errors (PARTIALLY FIXED)

**Original symptom:** 6+ pages with `aot-lazy-fareharbor-calendar.js` throwing silent JS exceptions (`Cannot read properties of null (reading 'style')`).

**Investigation finding:** The null-style error comes from FareHarbor's own embed script (`fareharbor.com/embeds/script/calendar/...`), not from `aot-lazy-fareharbor-calendar.js`. The loader is fine. The error is a third-party runtime issue.

**What was actually broken:** 4 pages with `jQuery is not defined` errors from pre-existing `defer=""` on jQuery scripts (see `aot-jquery-magnificpopup-fix-gro-4346-2026-07-28.md`).

**Fix (PR #129):** Removed `defer=""` from jQuery script tags on 12 pages. Verified fixed:
- `/activities/kawela-bay-self-guided-kayak-tour/` — jQuery 3.7.1 loads, jqReady=true, zero errors ✅
- `/activities/kawela-bay-self-guided-kayak-tour/ja/` — same ✅

**Not fixed (separate root cause):** `/rentals/explorer-oahu-kayak-rental-package/` — has a `jQuery is not defined` error from an unrelated inline script, not the gallery/magnificPopup issue. 0 other pages affected among 11 tested key revenue pages.

## GRO-4348 — FareHarbor `target="_blank"` Booking Links (NOT A BUG)

**Original claim:** 267 booking links across 33 tour pages have `target="_blank"` which bypasses the FareHarbor lightframe.

**Verification:** Playwright headless Chrome click test on `/activities/chinamans-hat-self-guided-oahu-kayak-tour/`:
- Clicked booking button with `target="_blank"` + `onclick="FH.open(...); return false"`
- Result: **0 new tabs opened**

**Root cause of the misconception:** `return false` in `onclick` prevents navigation, so `target="_blank"` never fires. The lightframe works correctly.

**Actual counts:**
- 720 FareHarbor links: `target="_blank"` + `onclick="FH.open(...)"` — harmless, works fine
- 12 FareHarbor links: `target="_blank"` without onclick — standalone links, not lightframe

**Verdict:** No broken lightframe behavior. The 267-count audit was a false positive. **Close as completed (not a bug).**

## GRO-4349 — Heading Hierarchy H5→H3 (ALREADY FIXED)

**Original claim:** 898 H5 tags across 134 files violate WCAG heading hierarchy.

**Verification:**
```bash
grep -rn "<h5>" site/ --include="*.html" | wc -l  # → 0
grep -rn "<h5 " site/ --include="*.html" | wc -l  # → 0
```

**Verdict:** Zero `<h5>` tags in committed HTML. This was either already fixed or the original audit was incorrect. **Close as completed.**

## Key Learnings

1. **Always verify with Playwright before claiming a bug exists.** The `target="_blank"` audit was a false positive — `onclick="return false"` prevents navigation.
2. **Always curl the live site before debugging.** Cloudflare Pages lag can make committed HTML differ from live HTML during the build window.
3. **The `execute_code` sandbox strips certain DOM modifications.** jQuery loaded but `window.jQuery` still returned false in sandbox. Use `terminal` with standalone Node.js Playwright scripts instead.
4. **Scope creep in task creation.** GRO-4347 conflated two separate issues: (a) jQuery errors from defer, (b) FareHarbor calendar null errors. These had different root causes and were fixed separately.
