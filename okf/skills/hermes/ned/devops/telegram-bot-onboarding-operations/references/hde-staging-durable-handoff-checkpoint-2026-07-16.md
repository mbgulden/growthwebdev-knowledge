# HDE staging durable handoff checkpoint — 2026-07-16

## Trigger

Michael asked to commit staging changes to a durable production place before family-test handoff, specifically avoiding workspaces/worktrees/branches losing live staging fixes.

## Durable checkpoint pattern

When HDE staging has live fixes spread across the staging repo, generated artifacts, and host-side guest template directories, do **not** only commit the obvious repo diff. First identify which runtime dependencies are outside Git and make the provisioning path durable.

### Steps

1. Inspect branch/remotes/status from `/home/ubuntu/work/hd-platform-staging`:
   - `git rev-parse --show-toplevel`
   - `git branch --show-current`
   - `git remote -v`
   - `git status --short --branch`
   - `git diff --stat`
2. Classify changes:
   - source/runtime code to commit,
   - generated handoff artifacts to commit or ignore,
   - runtime noise to remove/revert (`__pycache__`, empty SQLite fallbacks, generated monitor JSON/HTML if regenerated on demand),
   - external live template directories that need a repo snapshot.
3. For HDE guest runtime specifically, inspect `scripts/vm_orchestrator.py` for `TEMPLATE_DIR` and copied workspace items. If it points to `/home/ubuntu/guest_hermes_bot`, snapshot the template into the repo under `scripts/guest_hermes_template/` **excluding** `.env`, backups, and `__pycache__`.
4. Patch the orchestrator to prefer the repo-local template when present, falling back to `/home/ubuntu/guest_hermes_bot` only if absent:
   - `REPO_GUEST_TEMPLATE_DIR = Path(__file__).resolve().parent / "guest_hermes_template"`
   - `TEMPLATE_DIR = os.getenv("TEMPLATE_DIR", str(REPO_GUEST_TEMPLATE_DIR if REPO_GUEST_TEMPLATE_DIR.exists() else Path("/home/ubuntu/guest_hermes_bot")))`
5. Add `.gitignore` entries for regenerated/runtime artifacts, e.g. `staging_database.db`, generated family monitor HTML/JSON.
6. Run a focused `/tmp/hermes-verify-*` ad-hoc verifier before committing. It should prove:
   - repo guest template compiles,
   - live guest template compiles,
   - repo and live guest templates match when that is intended,
   - router/orchestrator/database/monitor compile,
   - `nginx -t`,
   - durable template wiring exists,
   - coach dashboard and protected API behavior still match expectations,
   - report auth and `Yes pdf report` media metadata still work,
   - secret scan passes.
7. Commit on a `ned/` branch with `[Ned] ...` prefix and push to origin. In this setup, origin may be the canonical local repo path `/home/ubuntu/work/hd-platform`; pushing there is still more durable than a dirty staging worktree.
8. After commit/push, run pre-handoff checks:
   - services active,
   - public checkout/dashboard routes return expected HTTP statuses,
   - `hde_guest_canary.py --guest-id 23 --pretty`,
   - family test monitor summary.
9. Clean any pycache regenerated by verification and confirm `git status --short --branch` is clean. Unlock files after commit.

## Pitfalls

- A clean Git commit is not durable if the live provisioning path still copies from an untracked host directory. Snapshot the guest template and wire the orchestrator to use it.
- Do not commit `.env`, token backups, pycache, empty fallback DB files, or transient monitor JSON/HTML unless they are intentionally handoff artifacts.
- Do not treat server-side canary proof as a real family handoff. Still require one real Telegram checkout → success page → deep link → `/start` → guide choice → chart PDF canary.
- `origin` may be a local canonical checkout, not GitHub. Report that plainly; durability means the branch is pushed out of the staging worktree, not necessarily published to a remote SaaS.
