# Sentinel ITAD repo consolidation pattern — 2026-07-08

## Context

The Sentinel ITAD/SIAL project had a canonical GitHub repo/workspace at `/home/ubuntu/work/sentinel-it-asset-logistics`, but older useful work lived in a loose non-git folder at `/home/ubuntu/work/sentinel-itad`. The user asked to bring “all the stuff we had before and the stuff we have now” together.

## Pattern

When consolidating a split project workspace:

1. **Identify canonical repo first**
   - Check git remotes, current branch, and project registry.
   - Confirm whether the older folder is a Git repo. In this case `sentinel-itad` was not a repo; `sentinel-it-asset-logistics` was canonical.

2. **Map legacy content into domain folders**
   - `docs/msp_outreach_kit.md` → `docs/outreach/msp_outreach_kit.md`
   - `docs/subcontract_loop_workflow.md` → `docs/operations/subcontract_loop_workflow.md`
   - `docs/sentinel_bin_placement_terms.md` → `docs/operations/sentinel_bin_placement_terms.md`
   - `docs/downstream_partners_research.md` → `docs/partners/downstream_partners_research.md`
   - `docs/facebook_marketplace_listing_guide.md` → `docs/resale/facebook_marketplace_listing_guide.md`
   - `docs/dl380_liquidation_kit.md` → `docs/resale/dl380_liquidation_kit.md`
   - `docs/ebay_setup_checklist.md` → `docs/resale/ebay_setup_checklist.md`
   - `ops/*.py` → canonical `ops/`

3. **Never migrate secrets/transients**
   - Skip `.env`.
   - Skip `__pycache__/` and generated bytecode.
   - Run a basic secret literal scan on migrated text/code before commit.

4. **Add a workspace index**
   - Create `docs/workspace-index.md` explaining canonical home, migrated paths, skipped paths, source-of-truth rule, and pending consolidation.
   - Update `README.md`, `okf/index.md`, `okf/research/index.md`, and the existing content map to point future agents to the canonical folder.

5. **Repair relative links after moving docs**
   - Legacy docs that linked to sibling files may need updated paths, e.g. operations docs now linking to `../partners/downstream_partners_research.md`.

6. **Verify before commit**
   - Use an ad-hoc `/tmp/hermes-verify-*` script when there is no canonical suite.
   - Check: expected migrated files exist/non-empty; no `.env` or preexisting `__pycache__`; basic secret regex; relative Markdown links resolve; migrated Python scripts compile with `python3 -m py_compile`.
   - Remove generated `__pycache__` after `py_compile` so the repo stays clean.
   - Run `git diff --check`; fix trailing whitespace from legacy docs before committing.

7. **Push/PR after commit**
   - Push the consolidation branch and open a PR so GitHub catches up to local reality.
   - Mention any unrelated pre-existing dirty file explicitly and leave it untouched.

## Pitfalls surfaced

- A canonical `npm run test` may exist in an adjacent helper repo but be a placeholder (`Error: no test specified`). Run it if asked, quote the failure, and keep the targeted ad-hoc verifier separate rather than editing unrelated package scripts.
- `python3 -m py_compile` creates `__pycache__`; delete it after verification.
- `git diff --check` can fail on legacy trailing whitespace. Strip whitespace in migrated files before staging.
- Project registry updates may live outside the target repo. Lock them separately if editing, and verify JSON validity with `python3 -m json.tool`.
