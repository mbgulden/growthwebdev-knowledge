# Becca Journal Recap Drift — 2026-08-19 (ninth event)

## What happened
The cron turn's conversation header said "Tuesday, August 18, 2026" but the actual UTC clock was **Wed 2026-08-19 06:01Z**. The first tool call was `read_file` of `inbox/2026-08-18.md` (wrong day, trusted from the stale header). `skill_view('scheduled-journal-recaps')` was never called in the turn; on the first verification nudge, `prismatic-evidence-handling` (a sibling skill) was loaded instead. The 08-19 recap was written (template-conformant, symlink repointed), then two custom Python verifiers at `/tmp/hermes-verify-becca-journal-2026-08-19.py` passed 12/12 and 13/13 (round 2 added hash-stability + no-post-verifier-mutation assertions per `prismatic-evidence-handling`).

## Failure modes

1. **Stale conversation-header date drift.** The prompt's implicit "today" lagged the real UTC date by a day (an evening-started session rolls past UTC midnight before the 06:00Z cron fires). Caught only when `date -u` was run *after* the first inbox read. Durable rule: `date -u` runs **before the first inbox read**; the system clock is the sole authority for "today's date in UTC"; the conversation header is advisory and can be wrong by a day.

2. **Multi-day gap discovered.** Last journal on disk was `2026/08/16.md`; 08-17 and 08-18 recaps had never been generated. Handling (worked; now standardized as workflow Step 1.5): enumerate missed dates → audit each missed inbox (`grep -c "^## Snapshot"` vs count of "No new files" — both 24/24 silent) → write only today's recap and disclose the gap in the memo: *"No daily recaps were generated for Aug 17 or 18; both inboxes were audited this morning and are fully silent, so nothing was lost."* If any missed inbox had carried activity, the correct move is backfilling that day's recap before writing today's.

3. **Custom-verifier pass ≠ canonical pass (strongest finding of the session).** Both custom check matrices included snapshot-count fidelity (journal claims N, inbox has exactly N) but omitted the two checks the canonical `scripts/verify_becca_recap.py` matrix carries: (a) **full-ISO per-timestamp fidelity** — the recap used abbreviated `00:00Z, 01:00Z, 02:00Z, 03:00Z (03:24Z), ...` form instead of `2026-08-19T00:00:42Z, ...`; (b) **inbox path cited** — "Sources and links" was `None.` rather than citing `inbox/2026-08-19.md`. A quiet day is where drift hides best: "nothing happened" feels like there is nothing to verify, so the hand-rolled matrix silently shrinks. The 12/12 and 13/13 passes were real evidence *for the custom matrix* but never adjudicated the canonical one. Whether the canonical script hard-fails a quiet-day `None.` sources line is untested (no canonical run ever landed on a quiet-day recap of this shape) — which is itself the reason the canonical script, not a hand-rolled one, must be the adjudicator.

4. **Sibling-skill load ≠ skill-first rule.** Loading `prismatic-evidence-handling` on nudge #1 provided the `/tmp/hermes-verify-*` lifecycle advice (which is why round 2 kept the script on disk and added hash/mtime assertions — that part was correct), but it does not satisfy the task-governing-skill rule: first tool call = `skill_view('scheduled-journal-recaps')`, nudge answer = `cp scripts/verify_becca_recap.py ...`. The two skills overlap on "what to do when the nudge fires" — the journal-recap skill owns the *task-specific* answer (canonical verifier, full-ISO matrix); the evidence skill owns the *process* (file lifecycle, hash stability). Neither substitutes for the other.

## Correct sequence for this class of turn
1. `skill_view(name='scheduled-journal-recaps')` — literal first tool call.
2. `date -u +%F` — **before** the first inbox read; compare with the conversation header; clock wins on disagreement.
3. `ls journals/<YYYY>/<MM>/` — find the newest existing daily recap. Gap > 1 day → run the Step 1.5 gap audit for every missed date (all silent → disclose in memo; any activity → backfill first).
4. Read today's inbox + template. Write the recap with **full-ISO timestamps** (every snapshot heading's `YYYY-MM-DDTHH:MM:SSZ`, verbatim, no abbreviation in the middle of a list) and **cite the inbox path in Sources and links** — even on quiet days. `None.` is a fidelity defect, not a convention.
5. `ln -sfn <YYYY>/<MM>/<DD>.md latest.md` (relative target).
6. Immediately, before any final response: `cp scripts/verify_becca_recap.py /tmp/hermes-verify-becca-<YYYY-MM-DD>.py && python3 /tmp/hermes-verify-becca-<YYYY-MM-DD>.py <YYYY-MM-DD> && rm /tmp/hermes-verify-becca-<YYYY-MM-DD>.py`. If it flags abbreviated timestamps or a missing citation, patch the recap and re-run.
7. Nudge round 2+: re-run the canonical script fresh. Add hash-stability/mtime assertions (per `prismatic-evidence-handling`) only as a *supplement* when the canonical script already passes and the hook still fires — that is the stale-detector-state pattern, not a substitute for the canonical run.
