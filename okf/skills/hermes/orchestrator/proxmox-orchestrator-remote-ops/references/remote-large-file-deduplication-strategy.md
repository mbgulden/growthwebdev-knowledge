# Remote Large File Deduplication Strategy\n\nWhen performing duplicate file audits on large remote filesystems (e.g., Proxmox backups on Synology NAS) via SSH, direct `sha256sum` on all files can lead to timeouts due to I/O and processing load.\n\n**Optimized Strategy:**\n\n1.  **Group by Size First**: Efficiently list all candidate files with their sizes. This can be done with `find <path> -name "*.vma.zst" -printf "%s %p\\n"` (adjust glob as needed). Group the results by size locally.\n    *   **Pitfall**: `find` itself can be slow on very large directories. Consider narrowing the search path if possible.\n\n2.  **Filter by Duplicates (by size)**: Identify groups of files that have identical sizes and have more than one entry. These are *potential* duplicates.\n\n3.  **Checksum Only Candidates**: For each group of potential duplicates (same size, multiple paths), compute the `sha256sum` for only those specific files. This drastically reduces the number of checksum computations.\n    *   **Command**: `sha256sum <path1> <path2> ...`\n    *   **Remote Execution**: When executing remotely via SSH (e.g., `sshpass -p "$PVE_ROOT_PASSWORD" ssh root@<ip> "sha256sum <paths>"`), ensure all file paths are properly shell-quoted to handle spaces or special characters within paths. The `hermes_tools.shell_quote()` function is useful for this.\n    *   **Environment Variables**: If the remote command relies on environment variables (e.g., `$PVE_ROOT_PASSWORD` for `sshpass`), ensure these are correctly passed into the `execute_code` environment or retrieved within the Python script using `os.environ.get()` if `execute_code` is used.\n\n4.  **Group by Checksum**: Finally, group the results by their SHA256 checksums. Any group with more than one file is a true set of duplicates.\n\n5.  **Report**: Generate a report (e.g., Markdown) listing each duplicate set, its total size, and the potential storage savings by keeping one copy and deleting the rest.
