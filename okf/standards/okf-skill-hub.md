# OKF skill hub — versioned skill registry

## Why

Skills were unversioned: 12 Hermes profile dirs, `~/.antigravity/skills/` (not
even a git repo), and four engine stores (`SKILLS/`, `.agents/skills/`,
`portable-skills/`, `prismatic/skills/`). Nothing tracked who owned a skill,
whether copies had drifted, or what changed over time. The 12-way divergence on
`pwp-qa`-class names proved silent drift is a live disease, not a hypothetical.

`okf/skills/` fixes that: every skill is mirrored 1:1 into git, versioned,
and catalogued with drift status.

## Layout

```
okf/skills/
  index.md      # human catalog: status counts, divergent backlog, full table
  index.json    # machine manifest: per-file sha256, per-skill status, generated_at
  hermes/<profile>/<category>/<skill>/SKILL.md   # 1:1 per-profile mirror
  agy/<category>/<skill>/SKILL.md                # 1:1 AGY CLI mirror
  prismatic/<store>/<skill>/SKILL.md             # 1:1 engine store mirrors
```

Per-profile subdirs are mandatory: they preserve divergence as-is so
reconciliation is a deliberate act, never a silent merge.

## Status vocabulary (index.md / index.json)

- **unique** — one store only
- **shared-N-identical** — N copies, byte-identical SKILL.md (safe mirrors)
- **divergent-K-variants** — same name, K different contents → reconciliation
  backlog, listed in the ⚠ section of index.md

## Regeneration

`python3 scripts/skill-hub-snapshot.py` — idempotent (guarded by
`.generated-by-skill-hub-snapshot` markers; wipes + re-imports only marked
trees). Run after any skill change and commit the diff; the index diff IS the
change report (new skill changes only — `generated_at` is derived from the
last commit date touching skill files, so no-op runs are byte-stable).
`SKILL_HUB_ROOT` env var overrides the hub path (portability / sandboxing).

## Rules

1. **Never edit generated files by hand.** Fix the source profile/store,
   re-run the generator, commit.
2. **Drift is a to-do, not a merge.** When index.md shows
   `divergent-K-variants`, reconcile per-skill on purpose: pick the canonical
   owner, update the other profiles' copies, re-run, and the status flips to
   `shared-N-identical`.
3. **Secrets never ship.** The generator copies verbatim; the verification
   scan (AKIA/Bearer shapes, example-tolerant) must pass before merge.
4. **Distribution is Phase B.** The hub is read-only registry today.
   `prismatic skills sync --source <okf-checkout>` (engine bootstrapper
   extension) is the planned fleet-distribution path; the engine never calls
   the OKF MCP — it reads a plain git checkout, keeping it portable.

## Verification

Ad-hoc: `/tmp/hermes-verify-skill-hub-phasea.py` (12 checks: exit, idempotence,
json/disk consistency, per-source 1:1 counts, markers, index sections,
secrets scan). No canonical suite exists for this generated tree; the
generator + verifier pair is the gate.
